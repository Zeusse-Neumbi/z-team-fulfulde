Z-Team Lingua

A language accessibility layer for Cameroonian digital financial services — Fulfulde and Yemba, without modifying the service.

Z-Team, Douala Version 2.0 — 14 November 2026 Technical note EN github.com/Zeusse-Neumbi/z-team-lingua

1. The problem

In Cameroon, many users of digital financial services speak a national language first, often only orally. Banking interfaces, mobile money and account-opening journeys remain mostly in French or English. The barrier is not only lexical: a user who is not fluent in French cannot check an amount, understand a fee, read a warning or confirm a beneficiary with the same confidence as a native reader.

Adamawa Fulfulde is a strongly oral language. Some of its speakers do not read the Latin orthography, even when they speak the language fluently. Voice is therefore not an add-on: it is a condition of access. In 2024, 60.9% of Cameroonian adults had a bank or mobile-money account (Global Findex 2025, World Bank); access is growing, but the interface remains in French or English.

2. The answer

Z-Team Lingua is a Chrome MV3 extension that translates the visible interface of an existing or simulated financial service in place, from French or English into a Cameroonian language, and speaks it when a voice is available. The service is not modified: the extension works on the page as an accessibility layer. Amounts, fees, totals, balances, names, phones, accounts, references and user input remain byte-identical.

What the demonstration proves

The page is translated in place

Five steps without a reload: balance, fees, beneficiary, summary, confirmation. Content added after load is handled by the MutationObserver.

Values stay exact

A mismatch on an amount, name, account or reference restores the changed nodes and aborts the plan. The check is byte-for-byte, not a fuzzy comparison.

Voice is a layer

The panel reads the step, facts, warnings and actions. It never reads the whole page; a sentence containing a protected value is excluded by default.

Nothing leaves the network

The extension talks only to 127.0.0.1. The value vault lives in memory and is cleared on Stop or navigation.

The demo path: SAFINUM page in French → enable → Fulfulde translation → voice → Yemba text switch → Stop and restore. Screenshots, checksums and the release are in the links above.

The project started as a Fulfulde assistant. The experiments showed that a model which “speaks” a language does not necessarily translate a financial interface. We measured, compared, and cut everything that failed the value invariant. These five experiments decided the architecture.

Three rules from the bench

01 · Measure values first

A sentence can be “fluent” and unusable if it loses an amount. The first criterion is not BLEU; it is value preservation and no looping.

02 · Mask before calling

No model receives a raw name, account or amount. Mixed nodes go through placeholders; if a placeholder dies, the target is refused.

03 · Label what remains

A draft that passes tests is still a draft. The panel, note, ZIP and release say MT — not validated until a speaker signs.

What survived: NLLB for Fulfulde, Marian for Yemba, MMS for the Fulfulde voice. What was cut: cameroon-int8 as the Fulfulde translator, M2M100 as the Yemba pack, and every clip whose draft is not speakable. The reasons are in ADRs 0018, 0019 and 0021.

5. Architecture: a language is data

The browser depends on no cloud service. The extension reads the page, applies the selected pack and verifies values; the local API receives only text that has already been filtered. The registry languages/<code>.yaml describes the language, pack, number lexicon, MT provider and voice policy. Adding a language changes neither the server, nor the translator, nor the extension.

Simplified diagram; the Mermaid source and detailed components are in docs/ARCHITECTURE.md.

6. The translation pipeline

1 · Readroles, accessible names, labels and text nodes. No bank-specific selector.
2 · Classifytranslatable, mixed, protected, ignore. Protected values never leave.
3 · Translatevalidated pack or MT draft. Mixed nodes are masked with [[Z1]].
4 · Verifyevery value is compared byte-for-byte; a mismatch restores the page and aborts the plan.

What stays in the browser

Amounts, fees, totals, balances, names, phones, accounts, references, dates, codes and user input. The vault is in memory and cleared on Stop or navigation.

What may reach the API

Only plain labels, or mixed labels whose values are replaced by placeholders. The target is applied only if every placeholder survives.

Tested invariant: 52 unit cases in packages/translator/src/integrity.test.ts, including a deliberate alteration that must trigger revert and abort. See ARCHITECTURE.md and PRIVACY.md.

The registry in practice

code: fub                 # ISO 639-3, one row per language
status: draft             # validated | draft | text-only
pack: entries/fub         # TM + phrases
numbers: numbers/fub.json # number lexicon
mt: { provider: nllb, pivot: fr }
speech: { provider: mms, voice: bundled }

One pack, one status

The loader rejects a missing pack, an unknown target or a malformed row. A validated pack without evidence breaks the build; a draft stays labelled.

One voice, one policy

bundled for Fulfulde, api for Yemba, none for text-only. The panel cannot borrow another language’s clips.

One proof, one language

Validation is per language: a Fulfulde speaker does not validate Yemba. The generated test stays red until sign-off.

Design boundary: the local API never sees a protected or unmasked mixed node. The pack decides the language and voice; the code contains no hardcoded language list.

8. Voice: what is bundled, what is not

Fulfulde bundled

facebook/mms-tts-ful, VITS, CC-BY-NC-4.0. 82 of 115 clips are playable; 33 are withheld because they are warnings, errors, ambiguous labels or repetitions. A clip plays only when the text matches the screen exactly.

Yemba API only

facebook/mms-tts-ybb, CC-BY-NC-4.0. No clips are bundled; without the local API, Play is disabled and the panel says why. A Fulfulde clip is never offered under the Yemba label.

The guard. pnpm check:evidence prints both packs and fails: Fulfulde 115/115, Yemba 103/115, 0 validated. build:release enforces evidence only for a language that declares status: validated (ADR 0020). That is deliberately weaker than validation: the ZIP is a labelled draft, not a linguistic release.

The protocol in three passes

1 · CorrectionFrench source visible, Fulfulde audio played; the speaker describes the error and the correct form.
2 · Blindaudio only; the speaker gives the French meaning and the team records the back-translation.
3 · Confirmationthe correction is re-synthesized; the speaker listens and confirms.
4 · Limitone speaker, oral review, no second written validation: the limit is written, not hidden.

What we do not claim

  • General Fulfulde or Yemba translation.
  • A measured MOS, naturalness or meaning score.
  • A validated voice, even when clips are playable.
  • Cross-validation between the two languages.

How to read the numbers

The 184 tests and 15 Playwright tests are dated 14 November 2026. The 30-page sweep is a 13 November snapshot. A number without a date is not evidence.

To validate

A Fulfulde speaker, then a Yemba speaker; the 115-clip pack, the CSV templates, the correction and blind passes. Sign-off ends with validatedBy and backTranslationFr.

After validation

pnpm check:evidence passes, build:release accepts the language, the panel reads validated, and clips are regenerated from corrected targets.

10. Reproduce in one command sequence

git clone https://github.com/Zeusse-Neumbi/z-team-lingua
pnpm install --frozen-lockfile
uv sync --project apps/server --frozen --extra dev
pnpm models:download mms nllb-ct2   # + mt-ybb mms-ybb for Yemba
pnpm build:submission
pnpm e2e
pnpm check:draft
pnpm check:evidence   # fails while the packs are drafts

The 1.10 MB ZIP is self-contained for Fulfulde and Yemba text translation; the Fulfulde voice is bundled, the Yemba voice needs the local API and model. The submitted commit is tagged and published in the release; checksums are in SHA256SUMS.txt.

11. Roadmap

  • Validation: a Fulfulde session, then a separate Yemba session; apply corrections and fill validatedBy and backTranslationFr.
  • Voice: evaluate the Yemba MMS voice, then fine-tune Fulfulde on a licensed corpus or move to recorded clips.
  • Languages: add a third language through the registry without touching the runtime; the Lamnso proof is already in the repository.
  • Product: partner integration, accessibility SDK, then other national languages.

What we do not do

No automatic click

The extension does not submit, check or validate for the user. A risky action is announced, then the user clicks it.

No cloud

No cloud provider by default, no runtime API key, no telemetry, no remote config. Weights stay in models/, never in the ZIP.

No real data

The demo uses fictional amounts, names, accounts and references. No real identifier is needed to load or test the extension.

No undated promise

Every claim points to a test, file, release or source. If evidence is missing, the sentence says “not measured”.
