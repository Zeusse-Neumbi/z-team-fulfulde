# 0021 — Adopt M2M100 for the Yemba candidate pack

- **Status:** accepted
- **Date:** 2026-11-14
- **Supersedes:** the Yemba part of `0019`/`0020` that names Marian as the
  `ybb` registry provider. The Fulfulde default stays NLLB.
- **Evidence:** [`docs/evidence/ybb-mt-comparison.md`](../evidence/ybb-mt-comparison.md)

## Context

`languages/ybb.yaml` resolved the `marian` provider to
`flagship-ai/cameroon-int8/francais-yemba`. The candidate pack generated with
that pair is degenerate: 11 of 20 financial sentences loop a phrase, the worst
12 times, and the placeholder mask fails on 3 TM units and 8 phrases.

`danyanderson/m2m100-yemba-french-fr2ybb` is a 418M M2M100 fine-tune, MIT,
FR→Yemba only, 1.85 GB fp32. On the same 20 sentences and the same CPU it kept
more digit groups (16 vs 14), repeated far less (4 rows vs 11; worst 4× vs 12×),
produced shorter output (1,139 vs 1,869 characters) and preserved 2/3 masked
placeholders versus 0/3 for Marian. It is ~19–24× slower: 24.1 s versus 1.27 s
median.

The four M2M100 repetitions are exactly the four sentences with a literal
amount. The extension never sends those: amounts are protected and masked before
MT. On the masked pack path the candidate is better, but not perfect — the
three-placeholder fee sentence corrupts its placeholders and must be withheld.

## Decision

1. **The `ybb` registry row uses the `m2m100` provider.** The provider loads the
   local `models/m2m100-yemba-fr2ybb` directory and refuses a non-French source
   with a typed 422.
2. **The Yemba candidate pack is regenerated with M2M100.** It stays
   `origin: mt`, `status: draft`, `packValidated: false`. Every placeholder and
   brand failure is withheld by the loader; no failed entry is shipped as a
   translation.
3. **Marian stays available as an explicit opt-in provider.** It is not deleted
   and its model directory is not removed. `ZTEAM_MT_BACKEND=marian` still
   works for a measurement run.
4. **Fulfulde does not move.** `fub` stays on NLLB per `0019`; M2M100 is a
   Yemba pair, not a general default.
5. **The model is a declared dependency of the Yemba draft.** The manifest
   entry is MIT, the downloader alias is `mt-ybb-m2m100`, and the model stays
   gitignored and out of the ZIP.

## Consequences

- A Yemba run needs a 1.85 GB download and more RAM than Marian. The panel and
  docs must state the local-only, FR-pivot and draft status.
- Latency for Yemba MT is tens of seconds per sentence on this CPU. The
  extension's cache and the phrasebank pack keep the user-visible cost down;
  the measured number is recorded rather than hidden.
- The licence improves from CC-BY-NC-4.0 to MIT for the Yemba text model.
  `THIRD_PARTY_NOTICES.md` lists both.
- The pack's `mtProvider: m2m100` and `mtModel` fields make the origin
  auditable. The release gate still refuses an unvalidated Yemba pack.
- The `__ybb__` token is marked special in the tokenizer; otherwise it leaks
  into decoded text. The server and both offline scripts share that rule.

## Reversal conditions

- A native speaker judges the M2M100 pack worse than the Marian pack on the
  same entries.
- A future M2M100 run withholds materially more entries than the 11 Marian
  failures, or corrupts a protected value in a validated entry.
- The 1.85 GB model or its latency makes the extension unusable on the target
  machine.
- The model licence changes or the weights become unavailable; then revert the
  registry row to `marian` and keep the M2M100 provider registered but opt-in.
